This page says which model runs by default, how a model call reaches it, and how to change it.

## The default

The default model is `@cf/deepseek-ai/deepseek-v4.1-flash-1017`. It runs on Workers AI. Your Cloudflare account pays for it, not a provider key. Workers AI usage settles at the end of the month. The benchmark below uses $0.011 per 1000 neurons.

## How a model call goes

The agent in the container sends OpenAI-style requests to `http://15.0.0.3/ai/v1`. That address is the capability gate. It is a private address that exists only inside your container. The gate runs in your Worker. It calls `env.AI.run(...)` on the Workers AI binding, which acts as your account. No token is stored in the container, in the config or on the Worker.

The binding routes the call through an AI Gateway, which gives logs and spend limits. An AI Gateway is Cloudflare's proxy in front of model APIs.

- The gateway is `default` unless you say otherwise. Cloudflare makes it on the first request, so `ochost init` makes no API call. Only the id `default` is made this way. Any other id must exist.
- `ochost init --gateway <id>` uses one you made. `--gateway none` runs without a gateway: no logs, no spend limit.
- The gate counts neurons per call against a daily budget. The default is 100,000 a day, about $1.10. Past it, calls get a 429. See and raise it with `ochost caps`.
- The gate skips the gateway cache for chat, so an agent reply is never repeated from cache.
- Some models (gpt-oss-120b, llama-3.3-70b, qwen3-30b) refuse an assistant message with `content: null`. OpenClaw sends that on a tool call. The gate changes it to an empty string.

```sh
ochost model list            # Workers AI models with tool calls; uses your wrangler login
ochost model set <id>        # new primary model; --fallback <id> adds a fallback
ochost model bench           # agent turns with tool calls through the gate
ochost ai-gateway setup      # choose the gateway; model test through the gate
```

`model set` sends one test message through the gate first. A model that does not exist, or a Claude model with no key on the gateway, stops there and changes nothing. Add `--restart` to apply a change at once. Without it, it applies at the next wake.

`ochost model bench` runs through the gate too. To bench a local copy of the Worker:

1. Run `npx wrangler dev` in the `worker` folder.
2. Run `OCHOST_CONTROL_TOKEN=<token> ochost model bench --gate-url http://127.0.0.1:8787`.

The binding still reaches your real account, so the bench bills you.

## Claude: your key stays in Cloudflare

Provider models are opt-in. They bill your own provider key, not Cloudflare credit. Today `anthropic/<model>` works. The key lives in the AI Gateway key store (BYOK). The container and the Worker never hold it. The Worker asks the binding for `anthropic/<model>`, and the gateway adds the key.

Do this once in the dashboard. The AI Gateway API needs a token that `init` does not have.

Cloudflare uses only a key with the alias `default` on this path. Without a key, the call falls back to Unified Billing (Cloudflare credit), or fails if the gateway has **Require provider credentials** on. The gateway needs authentication on, which the auto-made `default` has. The gate does not count Claude calls in neurons, only as requests. Set a spend limit on the gateway in the dashboard.

## Benchmark

`ochost model bench` sends agent turns with tool calls through the gate. One turn is a prompt with 4 tools. The model must call the right tool with the right arguments, then answer with the fact from the result. The results use 10 turns per model and one run each.

Short prompt:

| Model | Success | p50 turn | p95 turn | Neurons per turn |
|---|---|---|---|---|
| `@cf/meta/llama-3.3-70b-instruct-fp8-fast` | 10/10 | 1.62 s | 3.19 s | 37.6 |
| `@cf/openai/gpt-oss-120b` | 10/10 | 1.69 s | 6.62 s | 23.8 |
| `@cf/deepseek-ai/deepseek-v4.1-flash-1017` | 10/10 | 2.05 s | 6.01 s | 11.5 |
| `@cf/qwen/qwen3-30b-a3b-fp8` | 10/10 | 2.10 s | 4.01 s | 13.8 |
| `@cf/google/gemma-4-26b-a4b-it` | 10/10 | 2.20 s | 5.93 s | 7.6 |
| `@cf/nvidia/nemotron-3-120b-a12b` | 10/10 | 2.32 s | 3.38 s | 76.3 |

With a 13,000 token OpenClaw-shaped prompt, the same prefix each turn:

| Model | Success | p50 turn | Neurons per turn | USD per turn |
|---|---|---|---|---|
| DeepSeek V4.1 Flash | 10/10 | 2.51 s | 32.3 | 0.00035 |
| Gemma 4 26B | 9/10 | 2.59 s | 215.1 | 0.00237 |
| gpt-oss-120b | 9/10 | 2.78 s | 778.9 | 0.00857 |

DeepSeek has a prefix cache. A cold first turn costs 381 to 692 neurons, about $0.004 to $0.008. The first turn after a wake or a long idle is the cold number. We did not measure how often that happens.

The sample is small. Ten turns cannot rank latency. gpt-oss-120b, llama-3.3-70b and qwen3-30b need a string `content` in an assistant message to pass the second step of a tool turn. OpenClaw 2026.10.9 sends `null`. The gate now sends an empty string, so these models work. Gemma 4 26B is the recommended fallback. It is from another model family, and it works with `null`.
